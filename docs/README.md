# Documentation

Store architecture notes, decision records, setup guides, processes, and cross-domain reference material here. Documentation must be updated with the behavior it describes.

Material architectural, product, security, and operating decisions belong in `docs/decisions/`. Start from [`templates/decision-record.md`](../templates/decision-record.md) and use the filename format `YYYY-MM-DD-short-title.md`. A proposal becomes accepted or rejected; supersede an accepted decision with a new record, cross-link both records, and preserve the original rationale.
